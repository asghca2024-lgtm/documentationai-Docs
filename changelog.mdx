## Release Workflow

To keep your changelog useful, publish updates in a consistent order and keep each entry focused. A simple workflow helps you avoid clutter and makes it easier for learners to understand what changed.

<Steps>
  <Step title="Collect updates" icon="download">

    Gather release notes from documentation, course content, support, and site changes before you publish.

  </Step>
  <Step title="Review impact" icon="settings">

    Decide whether each change affects learners, instructors, or internal editors, then write the note accordingly.

  </Step>
  <Step title="Publish the entry" icon="check-circle">

    Add the update with a version label, date, and concise bullet list so readers can scan it quickly.

  </Step>
</Steps>

## Publication Formats

You can manage changelog content in different ways depending on your team size and publishing process. Use the format that best fits your workflow.

<Tabs>
  <Tab title="Markdown" icon="book-open">

    Use markdown when you want a simple, file-based changelog that is easy to edit and review in version control.

    ````markdown
    ---
    title: Changelog
    description: A running record of updates to the documentation, course offerings, and learner resources.
    ---

    ## Recent Updates

    <Update label="2026-05-15" description="v1.4.0" tags={["feature", "improvement"]}>

    ## New Features

    - Added a new release entry structure.
    - Expanded the changelog format.

    </Update>
    ````

  </Tab>
  <Tab title="Content team" icon="users">

    Use a shared editorial process when multiple contributors update the same documentation space. This keeps course edits, support changes, and learner resources aligned.

    ````text
    1. Draft the change note.
    2. Confirm the version label.
    3. Review the learner impact.
    4. Publish the update.
    ````

  </Tab>
  <Tab title="Automation" icon="zap">

    Use automation when you publish frequent updates and want a repeatable release pattern. This works well for scheduled course launches and documentation refreshes.

    ````json
    {
      "release": "v1.4.0",
      "date": "2026-05-15",
      "sections": ["new-features", "improvements", "bug-fixes"]
    }
    ````

  </Tab>
</Tabs>

## What to Track

Keep your changelog focused on changes that matter to readers. In a training and support environment, that usually includes new courses, revised exam guidance, updated resource links, and important site or support improvements.

| Change Type | What to Record | Why It Matters |
|-------------|----------------|----------------|
| Course additions | New exam preparation offerings or learning tracks | Helps learners find new options quickly |
| Content revisions | Updated lessons, guidance, or resource copy | Keeps information accurate and current |
| Resource improvements | Better downloads, links, or support references | Reduces friction for learners |
| Site changes | Navigation, layout, or accessibility updates | Improves the reading and browsing experience |

## Best Practices

- Write entries in past tense and keep them concise.
- Use a version label for every published update.
- Group similar changes together so readers can scan quickly.
- Put the most important learner-facing changes first.
- Keep the page self-contained so it works well as a reference without outside context.

<Callout kind="tip">

If you publish updates often, add a short summary line at the top of each entry and keep the detailed bullets under the relevant section headers.

</Callout>
